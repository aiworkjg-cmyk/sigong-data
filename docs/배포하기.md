# 배포하기

이 문서 하나만 따라 하면 Azure에 올라갑니다. 처음이라도 됩니다.

## 어디서 실행하나요

**전부 내 PC의 터미널입니다.** 셋 중 아무거나 상관없습니다.

- Claude Code 창 아래쪽 터미널
- 시작 메뉴 → `PowerShell`
- 시작 메뉴 → `cmd`

**단 하나 조건** — 폴더가 이 프로젝트여야 합니다. `azd` 는 현재 폴더의
`azure.yaml` 을 읽어서 동작하기 때문입니다.

```
cd C:\Dev\sigongdata
```

최초 배포 전 Azure 포털에서 배포 계정의 역할 할당 권한을 확인해야 합니다.

현재 배포는 `sigongdata-prod` 그룹의 기존 Linux B1 요금제
`ASP-sigongdataprod-8702`를 참조합니다. 새 App Service 요금제는 생성하지
않으며 기존 요금제의 등급도 변경하지 않습니다. 기존 요금제를 삭제하지 마세요.
다른 환경으로 배포할 때는 `infra/resources.bicep`의 `appServicePlanName`과
해당 리소스 그룹에 존재하는 요금제를 먼저 확인하세요.

소유자는 `sigongdata-prod → 액세스 제어(IAM) → 역할 할당 추가`에서 배포
계정에 `Role Based Access Control Administrator`를 추가할 수 있습니다.
기존 기여자 역할은 유지합니다. 조건으로 할당 가능한 역할을
`Storage Table Data Contributor`, 대상 유형을 `ServicePrincipal`로 제한하면
현재 템플릿에 필요한 저장소 역할 할당만 허용할 수 있습니다.

저장된 prod 환경으로 재개할 때 CMD에서 한 줄씩 실행합니다. 로그인은 권한을
부여받은 본인 계정으로 합니다.

```cmd
cd /d C:\Dev\sigongdata
azd env select prod
azd auth login
azd up
```

리소스 그룹에 권한을 부여했어도 구독 범위 사전검사 경고가 남을 수 있습니다.
해당 그룹의 역할과 조건을 확인한 뒤 진행하세요. 배포 후 코드만 갱신할 때는
`azd deploy`를 사용합니다.

## 무슨 일이 일어나나요

```
[내 PC]                            [Azure]
 C:\Dev\sigongdata                  ├ App Service  ← 서버가 여기서 돕니다
   ├ azure.yaml    ── azd up ──▶    ├ 저장소       ← 주문건·기록이 쌓입니다
   └ infra/                         └ 권한
```

`azd` 는 내 PC에서 도는 프로그램입니다. `infra/` 안의 설계도를 읽어 Azure에
"이렇게 만들어라" 하고 시킵니다. 예전에 포털에서 클릭하던 일을 대신합니다.

## 처음 한 번만

### 1. azd 설치

```
winget install Microsoft.Azd
```

> **설치 후 반드시 터미널을 새로 여세요.**
> 열려 있던 창은 새로 깔린 프로그램의 위치를 모릅니다. `azd : 용어가 …
> 인식되지 않습니다` 오류가 나면 십중팔구 이것입니다.

### 2. Azure 로그인

```
azd auth login
```

브라우저가 열립니다. 회사 계정으로 로그인하면 창이 닫히고 터미널로 돌아옵니다.

### 3. 환경 만들기

```
azd env new prod
```

`prod` 는 운영용이라는 뜻입니다. 나중에 시험용이 필요하면 `azd env new dev`
로 한 벌 더 만들 수 있습니다.

### 4. 비밀값 넣기

관리자 비밀번호와 SharePoint 연결 정보입니다. 코드에 적어 두지 않고 여기에만
보관합니다.

먼저 관리자 비밀번호의 해시를 만듭니다. 비밀번호 자체는 어디에도 저장하지
않고, 되돌릴 수 없는 형태로 바꾼 값만 씁니다.

```
npm run hash-password --workspace @jg/sigong-upload -- "원하는비밀번호"
```

> `--` 뒤에 비밀번호를 반드시 적어야 합니다. 빼면 사용법만 출력되고 끝납니다.

로그인 세션에 서명할 무작위 키도 하나 만듭니다.

```
node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
```

그 값들과 `apps/sigong-upload/.env` 에 있는 값을 아래처럼 넣습니다.

```
azd env set ADMIN_USERNAME admin
azd env set ADMIN_PASSWORD_HASH <해시값>
azd env set ADMIN_SESSION_SECRET <무작위값>
azd env set SHAREPOINT_TENANT_ID <값>
azd env set SHAREPOINT_CLIENT_ID <값>
azd env set SHAREPOINT_CLIENT_SECRET <값>
azd env set SHAREPOINT_SITE_ID <값>
azd env set SHAREPOINT_DRIVE_ID <값>
```

구글시트 연동을 쓴다면 서비스 계정 키도 넣습니다.

로컬 `.env` 는 키 **파일의 경로**를 가리키고 있지만, Azure 서버에는 그 폴더가
없습니다. 그래서 파일의 **내용**을 넣습니다. 앱은 둘 다 받도록 만들어져 있어
코드는 손댈 필요가 없습니다.

손으로 복사해 붙여넣지 마세요 — 수천 자에 따옴표가 많아 거의 확실히 깨집니다.
명령이 파일을 읽어 넣게 시킵니다.

cmd 에서:

```
powershell -Command "azd env set GOOGLE_SERVICE_ACCOUNT_JSON (Get-Content '경로\키파일.json' -Raw)"
```

PowerShell 에서:

```
azd env set GOOGLE_SERVICE_ACCOUNT_JSON (Get-Content '경로\키파일.json' -Raw)
```

아무 출력이 없으면 성공입니다.

넣은 값 확인:

```
azd env get-values
```

## 배포

```
azd up
```

처음 실행하면 구독과 지역을 물어봅니다. 지역은 **Korea Central** 을 고르세요 —
기사들이 한국에서 접속하므로 가까울수록 업로드가 빠릅니다.

5~10분 걸립니다. 끝나면 주소가 나옵니다.

```
https://sigongdata-prod.azurewebsites.net
```

### 잘 됐는지 확인

브라우저에서 `주소/api/health` 를 열어 `{"status":"ok"}` 가 보이면 서버가 살아
있는 것입니다. 그 다음 앱에 들어가 관리자 로그인 → 설정에서 SharePoint 연결
테스트 → 시험 업로드 순서로 확인하세요.

## 그 다음부터

| 상황 | 명령 |
|---|---|
| 코드만 고쳤을 때 | `azd deploy` |
| 인프라 설정(`infra/`)도 바꿨을 때 | `azd up` |
| 무엇이 바뀔지 미리 보기 | `azd provision --preview` |
| 서버가 뱉는 메시지 실시간 보기 | `azd monitor --logs` |
| 시험용 환경 한 벌 더 | `azd env new dev` 뒤 `azd up` |
| 지금 어느 환경인지 | `azd env list` |
| 만든 것 전부 삭제 | `azd down` |

`azd deploy` 는 코드만 올리므로 1~2분이면 끝납니다. 평소에는 이것만 쓰게
됩니다.

## 막혔을 때

**`azd : 용어가 … 인식되지 않습니다`**
터미널을 새로 여세요. 설치 직후 가장 흔한 문제입니다.

**`no project exists; to create a new project, run azd init`**
폴더가 다릅니다. `cd C:\Dev\sigongdata` 를 먼저 하세요.

**배포는 됐는데 화면이 안 뜸**
```
azd monitor --logs
```
서버가 시작하며 남긴 메시지가 보입니다. 대개 빠뜨린 환경 변수 이름이 그대로
찍혀 있습니다.

**옛날 화면이 그대로 뜸**
브라우저 강력 새로고침(Ctrl+Shift+R). 그래도 그러면 `azd deploy` 를 다시.

## 다음 프로젝트에 재사용하기

이것이 설정을 코드로 만든 이유입니다. 새 프로젝트에서:

1. `azure.yaml`, `infra/` 폴더를 복사
2. `azure.yaml` 의 `name` 을 새 이름으로
3. `infra/resources.bicep` 에서 그 프로젝트에 필요 없는 부분을 삭제
4. `azd up`

포털에서 무엇을 어떻게 클릭했는지 다시 기억해 낼 필요가 없습니다. Always On
을 켜는 것 같은 한 칸을 빠뜨릴 일도 없습니다 — 설계도에 이미 적혀 있습니다.

## 관련 파일

| 파일 | 역할 |
|---|---|
| `azure.yaml` | 무엇을 만들고 무엇을 배포하는지 |
| `infra/main.bicep` | 리소스 그룹 |
| `infra/resources.bicep` | App Service·저장소·권한 설계도 |
| `apps/sigong-upload/scripts/package-for-azure.mjs` | 올릴 폴더 준비 |
| `.github/workflows/deploy-sigong-upload.yml` | GitHub에 올리면 자동 배포(선택) |
