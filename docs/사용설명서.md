# 시공현장 자료 관리 시스템 — 사용 설명서

## 이 시스템이 하는 일

시공기사가 현장에서 찍은 사진·영상을 SharePoint의 정해진 폴더에 자동으로
정리해 보관합니다.

예전에는 기사가 카톡으로 사진을 보내면 사무실에서 하나씩 내려받아 폴더를
만들고 옮겼습니다. 그 과정에서 같은 현장이 여러 표기로 저장되고, 어느 건의
자료가 빠졌는지 아무도 알 수 없었습니다.

지금은 **사무실이 주문서를 한 번 넣으면**, 기사는 **목록에서 자기 현장을 고르고
사진만 올립니다.** 주소를 타이핑하지 않으므로 표기가 갈라지지 않습니다.

---

## 두 종류의 사용자

| | 시공기사 | 관리자 |
|---|---|---|
| 하는 일 | 사진·영상 올리기 | 주문서 등록, 현황 확인, 설정 |
| 로그인 | 필요 없음 | 필요 |
| 화면 | 자료 제출 하나 | 왼쪽 메뉴 전체 |

---

## 기사가 쓰는 법

주소를 열면 바로 나오는 화면입니다. 위에서부터 차례로 고르기만 하면 됩니다.

1. **시공종류** — 백조 / 인덕션 / 한샘 …
2. **현장종류** — 롯데백화점(흥주부) 같은 거래처. 고르면 나머지가 열립니다
3. **날짜** — 오늘 날짜가 기본
4. **시공건 선택** — 그 날짜의 현장 목록에서 고릅니다
5. **시공기사** — 실제로 다녀온 사람 (주문서의 예정 기사와 달라도 됩니다)
6. **사진·영상 첨부** — 최대 50개, 개당 100MB
7. **제출**

### 목록 / 달력 두 가지 방식

「시공건 선택」 오른쪽의 `목록 | 달력` 버튼으로 바꿉니다. 한 번 고르면
기억하므로 다음에도 같은 방식으로 열립니다.

- **목록** — 그 날짜의 현장이 지역별로 나열됩니다
- **달력** — 날짜를 눌러 그날의 현장을 고릅니다

### 목록에 없을 때

**「주문건 목록에 없음 — 직접 입력하기」** 버튼을 누르면 주문자명·주소·시공일을
직접 넣을 수 있습니다. 주문서 등록이 늦었거나 급하게 잡힌 현장을 위한 길입니다.

### 이미 올라간 건

파란색 배경에 **업로드 완료** 표가 붙습니다. 그래도 **다시 고를 수 있습니다** —
다른 기사가 잘못 올린 경우 그 건으로 다시 올려야 하기 때문입니다. 두 번째
제출은 폴더가 나뉘어 저장되므로 먼저 올린 자료를 덮어쓰지 않습니다.

### 개인정보

기사 화면에는 동호수와 연락처가 나오지 않고, 주문자 이름은 끝자가 가려집니다
(`신드*`). 현장에서 화면을 켜 두고 쓰기 때문입니다.

## 관리자가 쓰는 법

로그인 후 왼쪽 메뉴가 나옵니다.

### 주문서 등록·연동

기사에게 보여 줄 시공건 목록을 만드는 곳입니다. 두 가지 방법이 있습니다.

**① 구글시트 실시간 연동** (권장)

시트 주소를 한 번 등록하면 정해진 주기(기본 10분)마다 알아서 읽어 옵니다.

- **시트가 원본입니다.** 시트에서 줄을 지우면 여기서도 사라집니다.
  단, 이미 자료가 올라간 건은 남습니다.
- **탭 이름이 곧 현장종류**입니다. 탭을 추가하면 선택지도 따라 늘어납니다.
- **주문상태 열**만 보고 판단합니다. `취소` `시공완료` `시공x` 가 적혀 있으면
  가져오지 않고, 비어 있으면 대기 건으로 가져옵니다.
- 값이 덜 채워진 줄도 가져오되 **미완성**으로 표시합니다. 빼 두면 기사가
  현장에서 자기 건을 못 찾기 때문입니다.

**동기화 기록**에서 무엇을 왜 가져왔고 왜 뺐는지 시트별·사유별로 볼 수 있습니다.

**② 엑셀 파일 올리기**

시트를 안 쓰는 업체용입니다. 파일을 올리면 화면에서 확인한 뒤 등록합니다.

### 시공건 관리

등록된 시공건 전체를 보고 고치는 곳입니다.

- 기본 정렬은 **원본 시트의 줄 순서** — 시트와 나란히 놓고 대조하기 위해서입니다
- 날짜순·가나다순·지역순으로도 볼 수 있습니다
- 시공종류 → 현장종류 → 기사 → 권역 순으로 좁혀 볼 수 있습니다
- **미완성만** 버튼으로 값이 빠진 건만 따로 볼 수 있습니다
- 체크박스로 여러 건을 한 번에 수정·취소·삭제
- 달력 보기로 월·주·일 단위 확인

### 현장 목록 · 업로드 로그

기사가 제출한 자료가 실제로 SharePoint에 저장됐는지 확인하는 곳입니다.
필터를 걸어 조회한 결과를 **엑셀로 내려받을 수 있습니다.**

**수동 변경 기록**은 따로 있습니다. 앱을 거치지 않고 SharePoint에서 직접 올리거나
지운 흔적이 여기 남습니다. 사고가 났을 때 원인을 가려내는 용도라 업로드 로그와
섞지 않았고, 별도 파일에 계속 쌓여 사라지지 않습니다.

### 시공기사 관리

명부입니다. 팀장 → 사수 → 부사수 순으로 정렬되고, 직책·업체로 걸러 볼 수
있습니다. 추가·수정·삭제하면 기사 화면에 **바로** 반영됩니다.

### 설정

**시공종류별 입력 항목** — 업체마다 기사에게 물을 항목을 정합니다.
현장종류 선택지는 구글시트 탭 이름에서 자동으로 채워집니다.

**자료 업로드 입력 항목 차례** — 기사 화면에 항목이 나오는 순서를 시공종류마다
따로 정합니다. 필요 없는 항목은 빼고, 뺀 항목은 언제든 다시 넣을 수 있습니다.

**폴더 생성 규칙** — 두 단계로 정합니다.

1. 시공종류별 전용 규칙이 있으면 그것을 씁니다
2. 없으면 공통 기본 규칙을 따릅니다

`{시공종류}` `{연월일}` `{지역}` `{건물명}` 같은 **토큰**을 조합해 만듭니다.
버튼을 누르면 지금 고른 단계에 들어가고, 위에 단계별 미리보기가 나옵니다.

```
TEST › 백조 › 롯데백화점(흥주부) › 2026 › 08월 › 0809_경기 광명시_이편한세상
```

원하는 설정을 **기본값으로 저장**해 두면 나중에 언제든 되돌릴 수 있습니다.

**저장되는 파일 이름** — 공통 하나만 씁니다. `{번호}` 는 뺄 수 없습니다.
없으면 한 폴더의 파일이 모두 같은 이름이 되어 서로 덮어씁니다.

```
{폴더명}_{종류}{번호}  →  시공완료사진_이미지001.jpg
```

**Teams 알림** — 제출이 저장되면 지정한 채널에 카드가 갑니다.

**모바일 보기** — 상단 버튼을 누르면 기사가 보는 화면을 실제 휴대폰 크기
(360×780)로 확인할 수 있습니다.

## 자료가 저장되는 흐름

```
기사 제출
   ↓
서버가 접수하고 즉시 "완료" 응답        ← 기사는 여기서 화면을 닫아도 됩니다
   ↓
백그라운드에서 SharePoint로 전송
   ↓
폴더 규칙대로 폴더 생성 → 파일 이름 규칙대로 저장
   ↓
저장됐는지 되읽어 확인
   ↓
Teams 채널에 알림
```

영상은 몇 분씩 걸리므로 기사를 화면 앞에 붙잡아 두지 않습니다. 실패하면
자동으로 다시 시도하고, 그래도 안 되면 Teams로 알립니다.

**같은 현장에 두 번째 제출이 오면** 마지막 폴더에 `_중복방지-01` 이 붙은 새
폴더가 만들어집니다. 1차 시공과 재방문 자료가 한 폴더에 섞이지 않습니다.

## 시스템 구조

```
[기사·관리자 브라우저]
        │
        ▼
[Azure App Service]  ← 서버가 여기서 24시간 돕니다
        │
        ├──▶ [Azure Table Storage]  주문건·현장·로그
        ├──▶ [SharePoint]           사진·영상 원본
        ├──◀ [구글시트]              주문서 (읽기만)
        └──▶ [Teams]                제출 알림
```

| 구성 | 역할 |
|---|---|
| App Service | 앱이 도는 곳. 요금제 B1(Linux) |
| Table Storage | 주문건·현장·로그. 배포해도 사라지지 않습니다 |
| SharePoint | 사진·영상이 실제로 쌓이는 곳 |
| 구글시트 | 주문서 원본. 시스템은 읽기만 합니다 |
| Teams | 제출·실패 알림 |

## 자주 겪는 상황

**기사가 자기 현장을 못 찾는다고 할 때**
시공종류·현장종류·날짜를 맞게 골랐는지 확인하세요. 그래도 없으면 주문서가
아직 등록되지 않은 것입니다. 「직접 입력하기」로 올리게 하고, 나중에 관리자가
시공건 관리에서 확인하면 됩니다.

**동기화 건수가 안 맞을 때**
동기화 기록을 펼치면 시트별로 `총 항목 = 신규등록 + 갱신 + 변동없음 + 제외 +
건너뜀` 이 사유와 함께 나옵니다. 합이 안 맞으면 화면이 빨갛게 알려 줍니다.

**SharePoint에 파일이 덜 저장됐을 때**
현장 목록에서 그 건의 상태를 확인하세요. `일부 실패` 면 재시도할 수 있습니다.
파일 이름이 우리 규칙과 다르다면 SharePoint 쪽에 이름을 바꾸는 자동화가
돌고 있는 것입니다 — 그 경우 같은 이름끼리 덮어써서 개수가 줄어듭니다.

**설정을 바꿨는데 기사 화면이 그대로일 때**
브라우저 새로고침. 설정은 화면을 열 때 읽어 옵니다.
