# 작업 공간 (Workspace)

여러 사이트를 한 저장소에서 관리하는 모노레포입니다.
각 사이트는 `apps/` 아래 독립 폴더로 들어가고, 사이트들이 함께 쓰는 코드는 `packages/` 에 둡니다.

```
C:\dev\sigongdata\
├─ START.cmd                    더블클릭하면 로컬 서버 실행
├─ apps/                        사이트(배포 단위)
│  └─ sigong-upload/            시공현장 자료 수집·관리 시스템
│     ├─ src/                   프론트엔드 (React + Vite)
│     ├─ server/                백엔드 (Express)
│     ├─ scripts/               운영 스크립트
│     └─ package.json
├─ packages/                    사이트 간 공용 코드
│  └─ sharepoint-core/          SharePoint 업로드 + 폴더 분류 규칙
├─ docs/                        설정·배포 문서
├─ .github/workflows/           사이트별 배포 파이프라인
├─ package.json                 npm workspaces 루트
└─ tsconfig.base.json           공통 TypeScript 설정
```

## 빠른 시작

### 가장 간단한 방법

`START.cmd` 를 더블클릭하세요. 최초 1회는 필요한 파일을 내려받느라 몇 분 걸리고,
그 다음부터는 바로 서버가 켜지며 브라우저가 자동으로 열립니다.
**그 검은 창을 닫으면 서버도 함께 종료됩니다.**

### 명령어로 실행하는 방법

```bash
npm install
```

```bash
cp apps/sigong-upload/.env.example apps/sigong-upload/.env
```

```bash
npm run hash-password --workspace @jg/sigong-upload -- "로컬용비밀번호"
```

출력된 `ADMIN_PASSWORD_HASH` 와 `ADMIN_SESSION_SECRET` 을 `.env` 에 붙여넣은 뒤:

```bash
npm run dev
```

http://localhost:3000 에서 현장 등록 화면이 열립니다.
우측 상단 **관리자** 버튼 → 위에서 정한 아이디/비밀번호로 로그인하면 관리자 화면으로 들어갑니다.

SharePoint 나 Azure 설정이 없어도 그대로 동작합니다. 이 경우 파일은
`apps/sigong-upload/data/sharepoint_test_library` 에 실제와 동일한 폴더 구조로 저장되고,
기록은 같은 폴더의 JSON 파일에 저장됩니다.

## 자주 쓰는 명령

| 명령 | 설명 |
|------|------|
| `npm run dev` | 개발 서버 실행 (프론트 HMR 포함). `START.cmd` 가 이것을 실행합니다 |
| `npm run build` | 프론트 + 서버 빌드 |
| `npm run start` | 빌드 결과 실행 (운영과 동일한 경로) |
| `npm run lint` | 전체 워크스페이스 타입 검사 |
| `npm run hash-password --workspace @jg/sigong-upload -- "비밀번호"` | 관리자 비밀번호 해시 생성 |

## 로컬 서버는 어떻게 동작하나

`npm run dev` 하나로 **API 서버와 프론트엔드가 같은 포트(3000)에서** 함께 뜹니다.
Express 가 요청을 받아 `/api/*` 는 직접 처리하고, 나머지는 Vite 에 넘겨 화면을 그립니다.

```
브라우저 ──> http://localhost:3000
                     │
                Express 서버 (server/index.ts)
                     ├── /api/*  → 업로드 접수, 관리자 기능
                     └── 그 외    → Vite 개발 서버 (React 화면)
                                     화면 코드를 고치면 새로고침 없이 즉시 반영
```

운영 배포 시에는 Vite 대신 미리 빌드해 둔 정적 파일(`dist/web`)을 내보냅니다.
같은 코드가 로컬과 배포 환경에서 동일하게 동작하고, 달라지는 것은 환경변수뿐입니다.

`localhost` 는 "이 컴퓨터"라는 뜻이라 다른 기기에서는 열리지 않습니다.
현장 담당자가 접속하려면 배포가 필요합니다 ([docs/azure-deployment.md](docs/azure-deployment.md)).

## 새 사이트 추가하기

1. `apps/<사이트이름>/` 폴더를 만들고 `package.json` 의 `name` 을 `@jg/<사이트이름>` 으로 지정합니다.
2. 루트에서 `npm install` 을 한 번 실행하면 워크스페이스에 자동으로 연결됩니다.
3. `.github/workflows/deploy-<사이트이름>.yml` 을 추가합니다.
   기존 워크플로를 복사한 뒤 `AZURE_WEBAPP_NAME` 과 `paths` 필터만 바꾸면 됩니다.
   `paths` 필터 덕분에 한 사이트를 고쳐도 다른 사이트는 배포되지 않습니다.
4. Azure 리소스는 사이트마다 따로 만듭니다. 절차는 [docs/azure-deployment.md](docs/azure-deployment.md) 와 동일합니다.

### 공용 코드는 언제 `packages/` 로 옮기나

**두 번째 사이트가 실제로 같은 코드를 필요로 할 때** 옮기세요.
"나중에 쓸 것 같아서" 미리 공용화하면, 사이트마다 요구사항이 갈릴 때
공용 패키지가 분기 처리로 뒤덮여 오히려 유지보수가 어려워집니다.

현재 `packages/sharepoint-core` 는 SharePoint 업로드와 폴더 분류라는 뚜렷한 경계를 갖고 있어
분리되어 있습니다. 폴더 규칙이 데이터(템플릿 문자열)로 표현되어 있어서,
다른 사이트가 다른 분류 체계를 쓰더라도 코드를 고칠 필요가 없습니다.

## 주의사항

- **`.env` 파일은 절대 커밋하지 마세요.** `.gitignore` 에 등록되어 있으며,
  필요한 키 목록은 `.env.example` 에 정리되어 있습니다.
- **경로를 짧게 유지하세요.** Windows 의 260자 경로 제한 때문에
  `node_modules` 가 깊은 경로에 있으면 설치가 실패할 수 있습니다.
  작업 폴더를 `C:\dev\sigongdata` 같은 짧은 경로에 두는 이유입니다.
- **OneDrive 동기화 폴더 안에 두지 마세요.** `node_modules` 동기화 때문에
  빌드가 느려지고 파일 잠금 오류가 발생합니다.

## 앱별 문서

### sigong-upload — 시공현장 자료 수집·관리 시스템

현장 담당자가 **로그인 없이** 사진·동영상을 제출하면, 서버가 SharePoint 문서 라이브러리에
분류 폴더를 자동 생성하고 파일을 저장합니다. 관리자 계정으로 제출 내역, 업로드 로그,
이슈, 시공종류 설정을 관리합니다.

| 대상 | 접근 방식 |
|------|-----------|
| 현장 담당자 | 링크만 있으면 됨. 계정·로그인 불필요 |
| 관리자·업체 관계자·시공기사 | 아이디/비밀번호 로그인 |

#### 화면 구성

좌측 목록이 화면을 나눕니다. 링크로 접속하면 **시공현장 자료 제출**이 바로 열립니다.

| 메뉴 | 로그인 | 내용 |
|------|--------|------|
| **시공현장 자료 제출** | 불필요 | 현장 담당자용 제출 화면 (기본 화면) |
| **시공현황 리스트** | 필요 | 권한에 따라 조회 범위가 달라지는 시공 이력 |
| **시공기사 관리** | 마스터 / 관리자 | 기사 명부 추가·수정 |
| **시공종류 관리** | 마스터 | 시공종류 추가·삭제 |
| 마스터 전용 (현장 목록·로그·이슈·설정·계정) | 마스터 | 전체 운영 콘솔 |

로고를 누르면 언제든 제출 화면으로 돌아옵니다.

#### 관리자 계정과 권한

계정은 3단계이며, **마스터가 아니면 운영 콘솔 자체가 보이지 않습니다.**

| 권한 | 조회 범위 | 할 수 있는 일 | 어디서 만드나 |
|------|-----------|---------------|---------------|
| **마스터관리자** | 전체 | 모든 기능 + 계정·시공종류·설정 관리 | `.env` (또는 App Service 환경변수) |
| **관리자** (업체 관계자) | 담당 시공종류만 | 시공현황 조회(기사별·날짜별 필터), 기사 명부 추가·수정, 자사 시공기사 계정 생성 | 마스터가 [계정 관리]에서 생성 |
| **시공기사** | 본인 참여 건만 | 본인 시공 이력 조회 | 마스터 또는 업체 관리자가 생성 |

조회 범위는 **서버가 로그인 계정을 보고 결정**합니다. 브라우저가 다른 업체의 자료를
요청해도 서버에서 걸러지며, 범위를 벗어난 건은 404로 응답합니다.

업체 관리자는 기사 명부를 **추가·수정할 수 있지만 삭제는 못 합니다.** 삭제를 누르면
마스터가 지정해 둔 메일 주소로 요청하라는 안내창이 뜹니다 (주소는 [설정] 화면에서 변경).

#### 시공기사 명부

[시공기사 관리]에서 등록합니다.

| 항목 | 필수 | 내용 |
|------|------|------|
| 이름 | ✅ | |
| 직함 | ✅ | 팀장 / 사수 / 부사수 — 직함마다 파스텔 색상이 달라 한눈에 구분됩니다 |
| 소속 업체 | — | 시공종류 중 **여러 개 선택 가능**. 지정하지 않아도 됩니다 |
| 연락처 | — | |
| 담당지역 | — | |

**소속 업체는 곧 조회 범위입니다.** 업체 관리자는 자기 업체가 붙은 기사만 보고,
태그도 자기 업체 안에서만 붙일 수 있습니다. 업체 관계자가 직접 시공하는 경우
자신을 자사 소속으로 등록해 두면 됩니다.

업체를 지정하지 않은 기사는 **마스터에게만** 보입니다. 마스터 화면에서는 그런
기사에 "업체 관리자에게는 보이지 않음" 표시가 붙습니다.

한 기사가 여러 업체에 속해 있을 때, 백조 관리자가 편집해도 **한샘 태그는 그대로
보존**됩니다. 자기 몫만 바꿉니다.

제출 화면의 시공종류와 시공기사는 모두 **직접 입력이 아니라 목록에서 선택**합니다.
시공기사는 **여러 명을 함께 선택**할 수 있습니다. 검색은 자음 단위로 동작해서 `ㅎ` → `호` → `홍` 어느 단계에서든
홍길동이 나옵니다 (초성 검색, `src/hangul.ts`).

이름이나 직함을 나중에 수정해도 **이미 제출된 기록은 당시 값을 그대로 보관**합니다.

#### 시공현황 리스트

모든 권한이 필터를 쓸 수 있고, 필터 항목은 그 계정에 의미 있는 것만 나옵니다
(시공기사에게는 기사 필터가 뜨지 않습니다 — 결과가 언제나 본인뿐이므로).
기간은 입력창 두 개가 아니라 `시작 ~ 종료` 한 칸으로 지정하며, 오늘 / 최근 7일 /
최근 30일 / 이번 달 버튼이 함께 있습니다.

목록은 한 건당 두 줄로 고정됩니다. 첫 줄은 시공종류와 주소, 둘째 줄은
**시공 8/25 | 제출 8/24 | 기사 | 사진·영상 수** 로, 시공일과 제출일이 각각
라벨과 함께 붙어 헷갈리지 않습니다.

#### 폴더 생성 규칙

관리자로 로그인 → **[설정]** 화면에서 바꿉니다. 저장 즉시 다음 제출부터 적용됩니다.

```
시공현장자료 / 백조 / 2026 / 08월 / 0824_경기도광명시_이편한세상
└─최상위─┘   └────────── 하위 폴더 단계 ──────────┘
```

현장 폴더 이름은 **날짜_지역_건물** 입니다. 지역은 **시군구까지**, 건물은 아파트·건물
이름까지만 쓰고 **동·호수 같은 상세주소는 제외**합니다. 한 건물의 여러 세대가 하나의
폴더를 공유하게 하려는 것으로, 세대마다 폴더가 갈라지면 같은 현장 자료가 흩어집니다.

```
경기도 광명시 소하동 이편한세상 101동 1502호  →  0824_경기도광명시_이편한세상
경기 광명시 하안로 60 광명SK테크노파크 A동     →  0824_경기광명시_광명SK테크노파크
경기도 광명시 하안동  (건물명 없음)            →  0824_경기도광명시
```

설정 화면에서 **쓸 수 있는 항목이 버튼으로 제공**되고, 저장 전에 **미리보기**로 결과
경로를 확인할 수 있습니다. 값이 비면 앞뒤 구분기호(`_`)는 자동으로 정리됩니다.

**Teams 특정 채널에 저장하려면** 최상위 폴더를 `채널이름/시공현장자료` 처럼 적으면
됩니다. Teams 채널 파일은 사이트 문서함 아래 채널 이름 폴더에 들어가기 때문입니다.
(비공개 채널은 사이트 자체가 달라 `SHAREPOINT_SITE_ID` 를 그 채널 것으로 바꿔야 합니다.)

> ⚠️ 규칙을 바꿔도 **이미 저장된 폴더는 옮겨지지 않습니다.** 다음 제출부터 적용되므로
> 운영 중 잦은 변경은 피하세요.

시공기사 삭제를 시도하면 **등록된 전원에게** 요청 메일이 가고, 요청 창에도 수신자
목록이 그대로 표시되어 누구에게 가는지 보입니다.

#### 저장소 정보 노출

SharePoint 경로·폴더 구조·연동 상태는 **마스터관리자에게만** 보입니다. 다른 권한에는
화면에서 감추는 것뿐 아니라 **서버 응답에서도 제거**되어 나갑니다. 첨부파일은 경로 없이도
서버가 대신 내려주므로 열람에는 지장이 없습니다.

#### 모바일

제출의 대부분이 휴대폰에서 이뤄지므로 모든 화면이 모바일 우선으로 만들어져 있습니다.
관리자는 헤더의 **[모바일 보기]** 버튼으로 실제 390px 폭에서 화면을 확인할 수 있습니다.

마스터 계정 정보는 `apps/sigong-upload/.env` 의 `ADMIN_USERNAME` / `ADMIN_PASSWORD_HASH` 에 있습니다.
비밀번호는 해시로만 저장되므로 파일을 열어도 원문은 볼 수 없습니다. 바꾸려면:

```bash
npm run hash-password --workspace @jg/sigong-upload -- "새비밀번호"
```

출력된 `ADMIN_PASSWORD_HASH=` 줄을 `.env` 의 같은 줄과 바꿔 넣고 서버를 재시작하면 끝입니다.
(같이 출력되는 `ADMIN_SESSION_SECRET` 은 이미 값이 있으면 그대로 두세요. 바꾸면 로그인 중인
모두가 로그아웃됩니다.) 추가 계정의 비밀번호는 [계정 관리] 화면의 **비밀번호 재설정** 으로 바꿉니다.

#### 시공종류

관리자로 로그인 → **설정** 탭에서 추가·삭제합니다. 저장 즉시 제출 화면에 반영되고,
서버 재시작 후에도 유지됩니다. `.env` 의 `CONSTRUCTION_TYPES` 는 최초 1회 초기값일 뿐입니다.
삭제해도 이미 저장된 자료와 폴더는 그대로 남고, 앞으로 선택만 안 될 뿐입니다.

폴더 구조 (환경변수로 변경 가능):

```
시공현장자료 / {시공종류} / {연도} / {월}월 / {월일}_{주소}
예) 시공현장자료 / 백조 / 2026 / 08월 / 0811_경기광명시하안로60광명SK테크노파크
```

주요 동작:

- **제출 즉시 응답합니다.** 담당자는 자기 파일 전송이 끝나는 순간 완료 화면을 보고,
  저장소 반영은 서버가 뒤에서 처리합니다. 완료 화면에서 보관 진행률을 실시간으로 보여 줍니다.
- 시공종류와 시공기사는 정해진 목록에서 선택만 가능합니다 (값이 폴더 이름·기록에 그대로 쓰이므로 임의 입력 불가).
- 제출된 파일은 메모리에 담지 않고 디스크에 임시 저장한 뒤 순차 업로드합니다
  (100MB 동영상 50개를 받아도 메모리가 터지지 않습니다).
- 4MB 초과 파일은 Microsoft Graph 의 분할 업로드 세션으로 전송합니다.
- 저장 실패 시 자동으로 재시도하고, 그래도 실패하면 **관리자에게 메일로 알립니다.**
  실패한 파일은 임시 폴더에 남아 관리자 화면에서 다시 시도할 수 있습니다.
- 서버가 재시작되어도 처리 중이던 제출은 부팅 시 자동으로 이어서 처리됩니다.
- 모든 제출 시도는 업로드 로그에 기록됩니다 (성공/실패, 파일 수, 용량, 소요 시간, 접속 IP).
- 관리자 계정은 마스터 1개 + 화면에서 추가 생성하며, 관리자(업체)/시공기사 권한을 지정할 수 있습니다.
